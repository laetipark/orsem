# Discord 봇

Discord 프로세스는 MySQL과 분리되어 있습니다. 전송 대상 행을 기한부로 점유하며, 내부 NestJS 봇 API를 통해 조회 전용 슬래시 하위 명령을 제공합니다.

- `/orsem status`
- `/orsem recent [limit]`
- `/orsem company <query>`
- `/orsem market <region: kr|us>` — 국내·미국 각각 시가총액 상위 20개 종목과 기준일·월간 갱신 정보
- `/orsem news [region: all|kr|us] [limit: 1..5]` — 해당 시장 상위 종목과 시장 공통 뉴스

`DISCORD_BOT_TOKEN`, `DISCORD_APPLICATION_ID`, `DISCORD_CHANNEL_ID`, 무작위 `DISCORD_SERVICE_TOKEN`을 설정합니다. 개발 중 명령 등록을 빠르게 하려면 선택적으로 `DISCORD_GUILD_ID`를 사용합니다. `DISCORD_ALLOWED_USER_IDS`는 쉼표로 구분한 허용 사용자 목록이며 운영에서는 비워 두지 않습니다.

회사 이벤트 알림은 현재 월간 목록의 국내·미국 상위 20개 종목을 대상으로 합니다. 과거 운영 관심 목록은 사용하지 않으며, 대기 중인 전달도 수신 대상 조회와 확인 시 현재 시장 목록을 검사합니다. 수집 장애 같은 운영 알림은 별도로 유지합니다. 파싱이 완료되면 원본 Discord 메시지 ID가 있는 경우 해당 메시지를 편집하고, 조회·편집에 실패하면 후속 메시지를 보냅니다. Discord가 메시지를 받은 뒤 수신 확인이 유실될 수 있으므로 외부 전송의 완전한 중복 방지를 보장하지는 않습니다.

`recent`와 `company`는 기존 공시 이벤트 조회입니다. `news`는 제목 한 줄·제공 요약 한 줄·관련 종목·출처·KST 발행 시각·원문 링크만 표시하며, 긴 목록은 기사별 메시지로 나눕니다. 개인 관심 목록을 조회하지 않습니다. 네이버 뉴스는 기존 만료 메모리만 읽고 명령 실행으로 네이버 요청을 추가하지 않습니다. 기사 본문과 네이버 원본 응답은 봇 응답·명령 DB 기록에 포함하지 않습니다. 원문 주소가 안전한 HTTP(S) 주소가 아니거나 Discord 한도를 넘는 경우 해당 항목은 표시하지 않습니다.

시장 목록은 대표 종목 40개를 유지합니다. 뉴스·알림에는 월간 자료로 검증된 동일 기업의 다른 주식 클래스도 포함하며, 기사에 연결된 실제 종목 ID와 표기는 바꾸지 않습니다.

봇을 시작하면 슬래시 명령을 등록하고 실제 전송 대상을 처리하므로, 검증에는 `npm test -w @orsem/discord-bot`를 사용합니다.
