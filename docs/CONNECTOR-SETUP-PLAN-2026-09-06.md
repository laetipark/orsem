## 1. 화면에서 설정하는 관심그룹

1. Orsem에 승인된 계정으로 로그인합니다.
2. 홈의 시장 뉴스 아래 또는 **관심기업**에서 **새 그룹**을 누르고 이름을 입력합니다.
3. **종목 추가**에서 기업명·종목코드로 검색합니다. 국내와 미국 종목을 각각 넣어 확인하면 좋습니다.
4. **그룹 설정 → 승인된 서비스 회원에게 읽기 전용으로 공유**를 필요할 때 켭니다. 기본은 비공개입니다.
5. 다른 승인 계정에서 **공유 그룹 → 팔로우**를 선택하면 구독할 수 있습니다. 편집은 소유자만 가능합니다.

기존 운영 관심목록과 개인 그룹은 별개입니다. 개인 그룹을 편집해도 P1/P2 우선순위나 알림 설정이 바뀌지 않습니다. 뉴스 기업 분류·국내 종가 대체·최근 7일 집계는 별도 사용자 스위치 없이 적용됩니다.

자세한 화면 설명은 [관심종목 그룹 사용법](WATCHLIST_GROUPS.md)을 참고합니다.

## 2. NAVER Cloud 콘솔에서 먼저 확인할 것

기존 Application이 있으므로 신규 발급부터 시작할 필요는 없습니다.

1. NAVER Cloud 콘솔에서 **All Services → Application Services → NAVER API HUB → Application**을 엽니다.
2. Orsem에서 사용하는 Application에 **NAVER 검색 → 뉴스**가 선택되어 있는지 확인합니다.
3. **인증 정보**에서 같은 Application의 Client ID와 Client Secret인지 확인합니다. Cloud 키와 NAVER Developers 키는 혼용하지 않습니다. 키를 채팅에 붙여 넣지 말고 서버의 기존 비공개 설정 경로에서 비교·교체합니다.
4. **한도 및 알림**에서 현재 한도를 확인합니다. Orsem 전용 키라면 일 1,000회·월 30,000회를 초기 상한으로 설정할 수 있습니다. 다른 앱과 키를 공유하면 그 앱의 사용에도 영향을 주므로 전체 사용량부터 확인합니다.
5. **Usage Statistics**에서 해당 Application·검색 카테고리·당월을 선택하여 실제 사용량과 실패 호출을 확인합니다.
6. 서비스의 현재 무료 안내와 유료 전환 공지를 확인합니다. 공식 안내는 한시적 무료이며 고정 종료일을 명시하지 않습니다. 없는 종료일을 만들어 입력하지 않습니다.

콘솔 경로와 인증·한도 설정은 [Application 공식 안내](https://guide.ncloud-docs.com/docs/apihub-application), 사용량 조회는 [Usage Statistics 공식 안내](https://guide.ncloud-docs.com/docs/apihub-usagestatistics)를 기준으로 합니다. 공식 문서의 검색 카테고리 월 최대 775,000건은 계정의 실제 잔량이나 Orsem의 배정량이 아닙니다. 같은 키의 호출은 합산됩니다. [무료 조건과 공통 한도](https://guide.ncloud-docs.com/docs/apihub-overview)

### 서버에 반영할 설정

현재는 웹 관리자 화면에서 키·무료 자격을 입력하는 기능이 없습니다. 실행 단계에서 기존 비공개 환경 파일에 아래 항목만 반영합니다. `.env.example`은 설명용이며 수정해도 운영에 적용되지 않습니다.

| 환경 변수 | 설정 기준 |
| --- | --- |
| `NAVER_API_PROVIDER` | `ncloud` |
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 위 Application의 기존 키 쌍 확인; 필요할 때만 교체 |
| `NAVER_NEWS_FREE_MONTH` | 확인한 KST 월. 작성일 기준 `2026-09` |
| `NAVER_NEWS_FREE_REQUESTS` | Orsem에 배정한 **월 누적 상한**, 아래 계산 참조 |
| `NAVER_NEWS_DAILY_LIMIT` | 초기 `1000`, 필요하면 더 작게 |
| `NAVER_NEWS_MONTHLY_LIMIT` | 초기 `30000`, 필요하면 더 작게 |
| `NAVER_NEWS_FREE_UNTIL` | 시간대 포함 ISO 시각. 실행 전에 아래 기한 해석을 확정 |

`FREE_REQUESTS`는 남은 횟수 자체가 아닙니다. 현재 구현은 이 값에서 Orsem의 당월 사용량을 차감합니다. 당월 Orsem 사용량이 A, 계정 잔량에서 다른 앱의 몫을 제외하고 추가 배정한 양이 R이라면 월 상한은 `min(30000, A + R)` 이하로 잡습니다. 예를 들어 A=2,000, R=8,000이면 10,000을 설정하고 이 앱의 추가 호출 가능량은 8,000입니다. Orsem 카운터와 공급자 사용량은 집계 시차·공유 키 때문에 같지 않을 수 있으므로 안전 여유를 둡니다.

현재 코드는 `FREE_UNTIL`을 자동 중단 시각으로 사용하며, 현재 시각보다 미래여야 호출을 허용합니다. 공식 무료 종료일이 있으면 그보다 늦게 잡지 않습니다. 종료일이 없으면 **공식 무료 종료일과 운영자가 무료 공지를 다시 확인할 기한을 구분**해야 합니다. 짧은 운영 재확인 기한을 사용하는 경우 그 의미를 기록하고, 이를 공급자가 보장한 무료 기간으로 표시하지 않는 것이 이번 설정 계획의 전제입니다. 미래의 임의 날짜를 입력하는 것으로 무료 자격 확인을 대체하지 않습니다.

월이 바뀌거나 기한이 지나면 현재 구현은 자동·수동 검색을 모두 중단합니다. 무료 안내와 잔량을 다시 확인한 뒤 해당 월 설정을 갱신합니다. 반복 갱신 작업은 아직 예약하지 않았습니다.

적용 후 회사 상세의 **네이버 뉴스 원문 검색**에서 먼저 1회 결과를 확인합니다. 정상 조회와 사용량 차감·DB 미저장을 확인한 후, 필요한 화면에서만 **보는 동안 1분마다 새로고침**을 선택합니다. 401은 키, 403은 뉴스 API 권한, 429는 호출 한도, 시간 초과는 연결/응답 문제로 구분합니다.

## 3. SEC EDGAR 설정과 진단

SEC 회사 공시 데이터 API에는 API 키 발급이 필요하지 않습니다. 애플리케이션 이름과 실제 확인하는 이메일이 포함된 User-Agent를 사용합니다. 공식 접근 정책은 최대 초당 10회와 효율적인 요청을 요구합니다. [SEC 접근 기준](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)

설정 형태는 `SEC_USER_AGENT="Orsem 실제연락이메일"`입니다. 기존 값이 정확하면 유지합니다. 회사 CIK는 회사별 식별자이며 사용자 개인 키가 아닙니다.

배포 검증에서 유효한 식별 정보에도 403이 발생했으므로, 키 재발급이나 User-Agent 변경을 해결책으로 단정하지 않습니다. 현재 worker에는 요청 간격 최소 250ms와 403/429 후 최소 10분 대기, 더 긴 Retry-After 존중이 적용되어 있습니다. 간격 직렬화는 현재 단일 worker 프로세스 기준이며, 대기 기록은 DB에 보존됩니다.

실행 순서는 저장된 대기 종료 확인 → 운영 worker의 단일 회사 요청 → 응답 상태·헤더 전달·DNS·프록시·TLS·송신 경로 대조입니다. 실제 200 응답과 공시 식별자·접수일 저장, 회사 화면 조회까지 확인해야 복구 완료입니다. 403이 지속되면 반복 강제 호출 대신 확인된 차단 상태와 지원 문의에 사용할 비밀값 없는 진단 내용을 정리합니다.

## 4. GDELT 설정과 확인

GDELT는 세계 뉴스 발견용 공개 데이터입니다. Orsem의 현재 DOC API 경로는 가입이나 API 키를 사용하지 않습니다. [GDELT 소개](https://www.gdeltproject.org/about.html)

운영에는 이미 아래와 같이 활성화되어 있습니다.

```dotenv
GDELT_ENABLED=true
GDELT_NEWS_DOMAINS=
```

`GDELT_NEWS_DOMAINS`를 비우면 기본 관심기업·거시경제 검색을 사용합니다. 특정 도메인으로 좁힐 때만 스킴·경로 없는 도메인 목록을 넣습니다. 30분 간격은 현재 코드의 일정이며 별도 환경 변수로 변경하는 기능은 없습니다.

실행 단계에서는 새 스케줄을 중복 생성하지 않고 기존 예약과 worker 활성 상태, 마지막 실제 요청, 다음 재시도 시각을 확인합니다. 응답이 돌아오면 제목·출처·언어·링크만 저장하고 URL 중복 제거·기업 연결·발행일/최초 확인 표시를 검증합니다. 정상 응답이지만 검색 결과가 없는 경우와 요청 실패도 구분합니다. 429나 시간 초과 상태를 키 누락으로 처리하지 않습니다. GDELT의 최소 요청 간격은 5초이고 429 대기는 현재 worker 메모리에 있으므로 재시작을 반복해서 해제하지 않습니다. 연결 시간 제한 변경이 필요하면 전체 커넥터 공통 값을 무작정 높이지 않고 GDELT 영향 범위를 먼저 확인합니다.

2단계의 계정 정보가 없어도 SEC/GDELT의 읽기 전용 상태 점검과 그룹 UI 확인은 병행할 수 있습니다. 실행 전 설정과 기존 산출물을 백업합니다. 현재 작업 트리의 미배포 번역 편집 코드를 포함하는 전체 빌드·전체 마이그레이션은 이 설정 작업에 필요하지 않습니다.

환경 반영 시 현재 PM2의 다른 설정과 비교하여 해당 커넥터의 환경 키만 갱신합니다. 단순 `pm2 restart`는 이전 환경이 남을 수 있으므로 변경값 전달과 실제 적용값을 검증합니다. API/worker 중 필요한 프로세스만 재시작하고 Ollama·Discord와 다른 서비스는 건드리지 않습니다. 환경만 바꾸는 단계에는 DB 마이그레이션·웹 재빌드가 없습니다. 전역 `pm2 save` 대신 Orsem 대상의 재부팅 복원 값만 검증합니다.

NAVER 확인에 필요한 전달 항목은 **Application에 뉴스 권한이 있는지, 현재 무료 공지 확인 결과, 당월 검색 사용량과 설정 한도, 키를 다른 앱과 공유하는지**입니다. Client Secret이나 계정 비밀번호를 채팅으로 전달할 필요는 없습니다.
