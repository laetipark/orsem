## 반영한 기능

- `/watchlist-groups`: 세션 소유권, 개인 그룹 CRUD·정렬·종목 관리, 승인 이용자에게 읽기 전용 공유, 팔로우·해제.
- 홈 시장 뉴스 아래와 관심기업 페이지의 공통 그룹 패널: 21종목 페이지, 보일 때 60초 갱신, 카드/목록, 20개 일봉, 가격·등락 기준일, 최근 7일 공시·이벤트.
- 공시·이벤트는 KST 오늘 포함 7일의 접수·발표일로 집계합니다. 실제 발생일은 별도 표시하며 최신 목록의 공시·파생 이벤트 중복을 제거합니다.
- 개인 그룹은 기존 운영 관심목록/P1·P2/외부 알림 설정과 분리합니다. 승인 소유자의 개인 종목은 시세·SEC·GDELT 수집 합집합에 포함하며 기존 시세 구독 상한을 유지합니다.
- 뉴스 다중 기업 관계, 기본 회사명·명시적 종목코드·티커·추가 별칭, 모호한 일반 단어 제외, `/news?scope=all|market|company`와 기업 관계별 조회.
- GDELT는 제목·출처·언어·원문 링크만 수집합니다. 본문·이미지·번역을 추가하지 않고 발견 시각과 발행일을 구분합니다.
- NAVER는 별도 검색 화면에만 응답을 표시합니다. 검색어·응답은 DB·백업·번역 모델에 저장하지 않으며 사용량 숫자만 영속 집계합니다.

사용자 안내: [관심종목 그룹 사용법](WATCHLIST_GROUPS.md).

## DB와 배포 범위

이번에 적용한 마이그레이션은 아래 두 개뿐입니다. `synchronize=false`, 자동 마이그레이션도 꺼져 있습니다.

| 마이그레이션                            | 추가 테이블                                                            |
| --------------------------------------- | ---------------------------------------------------------------------- |
| `1788406000000 AddWatchlistGroups`      | `watchlist_groups`, `watchlist_group_items`, `watchlist_group_follows` |
| `1788407000000 AddNewsCompanyRelevance` | `news_source_companies`                                                |

기존 FK 열과 동일한 `utf8mb4_unicode_ci`를 명시했습니다. 기존 기사 90건을 계산해 관련 기사 54건·회사 관계 55개를 저장했습니다. 두 번째 적용에서 관계 행의 내용·시각이 변하지 않았고, 전후 원문·번역·권리·기존 운영 관심목록·계정 상태 해시가 같았습니다.

운영 뉴스 조회에서 본문·번역 검증을 통과한 32건 중 시장 공통 17건, 기업 관련 15건이 서로 겹치지 않는 것을 확인했습니다. 이는 배포 시점 데이터이며 전체 수집량과 다릅니다.

현재 작업 트리에는 이번 범위가 아닌 수동 번역 편집 기능이 있습니다. `1788405000000 AddManualNewsTranslations`와 해당 API 등록·SQL 컬럼을 이번 운영에 포함하지 않았습니다. 현재 작업 트리 전체의 `build`나 전체 `migration:run` 결과를 이 배포본에 그대로 덮어쓰면 안 됩니다.

배포 후보는 기존 운영 산출물에서 시작해 이번 API/worker 모듈 44개 변경을 반영했습니다. DB의 기존 entity 정의에 새 네 개 entity만 추가했습니다. 기존 자동 번역 reader·worker는 유지하고 수동 번역 SQL/등록은 후보에서 제외했습니다. 변환은 TypeScript AST 및 단언으로 검사했고 실제 DB에서 목록·상세·검색을 실행했습니다. 웹은 `fixture=false`, `manual-editor=false`, API `/api/v1`로 격리 빌드했습니다.

## 실제 수집 상태

| 항목        | 운영 검증 결과                                                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NAVER Cloud | 자격 증명은 설정됨. 이번 달 무료 기간·잔량 미확인으로 자동·수동 호출 모두 차단. 실제 검색 성공은 이번 배포에서 확인하지 못함.                                                     |
| SEC         | 기존 대기 중에는 미호출. 대기 종료 후 단일 NVDA 경로의 실제 요청은 403. 새 공시 저장 0건이며 복구 완료로 간주하지 않음.                                                           |
| GDELT       | `GDELT_ENABLED=true`, 30분 정기 수집 활성화. 소량 검증 두 번은 실제 429였고, 02:30 KST 첫 정기 작업도 실행됐으나 연결/응답 시간 초과로 0건 저장. 다음 작업은 03:00 KST로 예약됨. |

SEC User-Agent는 운영 환경 파일과 일치하고 형식도 유효했습니다. Node v24.14.1, 공개 DNS IPv4/IPv6 응답, 프록시 환경 부재, TLS 검증 우회 부재를 확인했습니다. 이것으로 403의 IP·속도 차단 원인을 단정하지 않습니다. 상태 화면은 실제 요청/대기 중 미요청, 마지막 요청·성공, 재시도 가능 시각을 구분합니다.

GDELT의 재시도 대기는 현재 worker에서 유지되며 30분 정기 수집은 계속됩니다. 02:30 KST 작업의 실제 시작·종료와 다음 예약을 Redis에서 확인했습니다. 작업 실행 완료와 기사 수집 성공은 구분하며, 아직 새 기사 수집 성공은 확인하지 못했습니다. 재부팅 복원에서도 활성화되도록 PM2 저장 파일의 **orsem-api/worker 두 항목의 GDELT 플래그만** 갱신했습니다. 다른 프로세스의 저장 설정은 바꾸지 않았고 전역 `pm2 save`는 실행하지 않았습니다.

NAVER를 켜려면 무료 조건과 계정 공유 사용량을 확인한 뒤 다음 값을 설정하고 API를 재시작합니다. 공급자 계정 전체의 남은 양을 이 앱의 카운터만으로 알 수는 없습니다.

| 환경 변수                  | 기준                                                     |
| -------------------------- | -------------------------------------------------------- |
| `NAVER_NEWS_FREE_UNTIL`    | 확인한 무료 이용 기한, 시간대 포함 ISO 시각              |
| `NAVER_NEWS_FREE_MONTH`    | 확인한 KST 월, `YYYY-MM`                                 |
| `NAVER_NEWS_FREE_REQUESTS` | 계정 잔량과 다른 앱 사용량을 반영한 이 앱의 월 누적 상한 |
| `NAVER_NEWS_DAILY_LIMIT`   | 최대 1,000                                               |
| `NAVER_NEWS_MONTHLY_LIMIT` | 최대 30,000                                              |

미설정·만료·월 변경·사용량 확인 실패 때는 호출하지 않습니다. 실패/응답 유실 요청도 예약량에서 차감하며 자동·수동이 같은 한도를 사용합니다.

## 검증과 수정 사항

- 웹 전체 258개 테스트, 최종 로그인 문구 8개 테스트; 그룹·권한·가격 서버 61개, 뉴스/SEC/GDELT worker 및 API 회귀 검사 통과.
- 실제 활성 관리자와 승인 회원 각각 하나로 서비스/SQL CRUD·교차 비공개 접근 거절·공유 조회·구독자 편집 거절·공유 해제·재공유·삭제를 검증했습니다. 임시 그룹은 모두 삭제했고 계정 승인 상태는 바꾸지 않았습니다.
- raw SQL의 문자열 `'0'`을 JavaScript 참으로 읽는 문제를 실제 DB 검증에서 발견해 공유·팔로우·목록 중복 처리에 명시적 boolean 변환을 적용했습니다.
- 모든 별칭을 검사하던 병목을 접두부 색인으로 개선했습니다. 실제 9,140기업·40,560별칭 규모와 같은 합성 90기사 시험은 약 0.4초, 운영 90기사 예행 실행은 프로세스 포함 약 0.6초였습니다. 기존/신규 매처 510개 경계·Unicode·대소문자 사례의 동등성도 확인했습니다.
- 운영 패널: 삼성전자 257,000원(9/4 종가)을 248,000원(9/3 종가)과 비교해 +9,000원/+3.629% 반환, 실제 20개 일봉 확인. NVDA는 기존 미국 체결가 정책 유지. KST 창은 8/31–9/6.
- 이전 Qwen 수정 31개 제목·요약, 16개 본문의 내용·원문·권리 정보 보존 및 기존 운영 reader 통과.
- API 준비 상태 200, 익명 그룹/뉴스/NAVER 상태 API 401, 공개 웹 200. API·worker PID 안정, 모든 큐 재개, Ollama·Discord PID 유지.
- 로그인된 운영 브라우저 세션은 없어 실제 두 브라우저 로그인 공유 흐름은 확인하지 못했습니다. 실제 두 계정의 서비스/SQL 검증, HTTP guard 테스트, 합성 응답으로 데스크톱·모바일 UI 검증을 구분해 기록했습니다. 모바일 가로 넘침·브라우저 오류는 없었습니다.
