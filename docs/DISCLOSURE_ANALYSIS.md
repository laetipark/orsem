# 공시 분석실

공시 분석실(`/analysis`)은 승인 회원과 관리자가 기업의 재무를 비교하고, 원문과 변경 내역을 확인하며, 실행 결과를 XLSX로 받는 기능입니다. 기업 화면·관심그룹·공시 상세에서도 해당 조건으로 진입합니다.

## 활성화

1. `1791590400000-AddDisclosureAnalysis`를 포함한 마이그레이션을 적용합니다. 기존 기업정보 스냅샷은 여러 기간을 포함하므로 비교용 재무 데이터로 이관하지 않습니다. TypeORM `synchronize`는 계속 `false`입니다.
2. API·웹과 Python 워커를 함께 배포합니다. 워커의 고정 의존성에는 `openpyxl==3.1.5`와 `et-xmlfile==2.0.0`이 추가됩니다.
3. API와 워커에 같은 단계별 설정을 적용합니다. `ANALYSIS_ENABLED=true`는 국내 재무 비교와 엑셀, `ANALYSIS_DOCUMENTS_ENABLED=true`는 미국 재무·원문·정정·SEC 내부자 문서, `ANALYSIS_NOTES_ENABLED=true`는 주석 검색과 북마크를 활성화합니다. 기본값은 모두 `false`입니다.
4. 기존 `RAW_DOCUMENT_DIR`에 원문과 내보내기 파일을 보관합니다. 저장소 밖의 영속 경로를 사용하고 기존 원문 객체를 덮어쓰지 않습니다.
5. 국내 기업부터 제한된 범위로 수집·검증합니다. SEC 접근 실패는 국내 기능 공개를 막지 않습니다. 운영 환경에 샘플 기업·재무·공시를 자동 삽입하지 않습니다.

설정이 없는 커넥터는 해당 자료만 사용할 수 없습니다. SEC는 기존 식별 가능한 User-Agent, 공유 요청 간격과 차단 대기 정책을 사용합니다. 403·429 또는 DART 요청 제한은 완료 상태가 아니며, 다시 요청할 수 있는 시각까지 기다립니다.

## 비교 기준

- 기본 조회는 최근 3개년이며 최근 8개 분기로 전환할 수 있습니다. 기업은 최대 20개, 기간은 최대 20개입니다.
- 연결과 별도, 연간·단독 분기·누적·기말 잔액을 분리합니다. 다른 통화를 자동 환산하거나 연결 자료를 별도 자료로 대체하지 않습니다.
- 누락·미지원·계정 대응 모호함은 0이 아닙니다. 원문 금액과 계산용 십진 문자열을 함께 보존합니다.
- 공식적으로 제공되는 단독 분기 값만 사용합니다. 제공되지 않은 4분기·현금흐름 단독값을 서로 다른 제출본의 누적 수치로 임의 차감하지 않습니다.
- 실제 회계기간을 확인할 수 없는 수치로 증감률을 계산하지 않습니다. 전기 값이 0 또는 음수이면 증감률 대신 차액과 해당하는 이익 전환 여부를 표시합니다.
- ‘최초 관측본’은 ORSEM이 보존한 첫 응답입니다. 최초 제출 당시의 값과 같다고 보장하지 않습니다. [OpenDART 전체 재무 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)는 요청에 특정 접수번호를 받지 않습니다. 실제 날짜 확인에는 동일 제출본의 [주요계정 응답](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019016)을 사용합니다.
- SEC Companyfacts는 표준 계정·기업 전체 재무의 경로입니다. 기업 고유 계정과 사업부 주석 전체를 제공한다고 가정하지 않습니다. [SEC API 안내](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)

## 개인 기록과 원문

분석 실행은 조건·기업 목록·제출본·수치·매핑 버전을 고정합니다. 저장한 조건은 수동 갱신이 기본이며, 자동 갱신을 선택한 조건만 새 공시 관측 후 실행합니다. 관심그룹 접근권한은 새 실행 시 다시 확인하고 이전 개인 결과는 보존합니다. 실행 생성과 작업 등록은 같은 데이터베이스 트랜잭션으로 처리합니다.

자동 갱신 대상 국내 기업의 A001~A003 정기보고서는 시간당 제한된 범위로 확인합니다. 기존 지분공시 거래 파서나 알림에 정기보고서를 보내지 않습니다. 미국은 기존 SEC 관측 결과를 사용합니다. 한 기업의 제공자가 대기 상태여도 다른 기업의 확보된 수치는 보존하며 전체 실행을 수집 완료로 표시하지 않습니다.

원문은 HTML을 실행하지 않고 추출한 텍스트와 표로 표시합니다. 확정되지 않은 원문 셀 대응과 정정 관계는 검토 상태로 표시합니다. D001·D002·D005의 의미는 유지하며 D005는 거래 계획입니다. SEC의 P/S 코드나 수량 증가만으로 장내매매를 단정하지 않습니다.

SEC의 `/A` 표시만으로 이전 제출본을 추정하지 않습니다. 자동 확인할 공식 관계가 없으면 관리자가 같은 기업의 두 원문과 공식 HTTPS 근거·검토 사유를 확인한 뒤 비교를 요청합니다. 확인 기록은 보존되며 완료된 비교를 다시 덮어쓰지 않습니다. 표의 행 이동과 실제 값 변경을 구분하고, 본문·날짜·단위·XBRL 계정의 변경도 확인합니다. 중복된 제목이나 행의 대응은 추측하지 않습니다.

XLSX는 생성 요청 당시의 실행 결과를 사용합니다. 조회 조건·원문값·출처·미확보 자료와 선택한 문서 내용을 포함하며, 정밀도가 큰 숫자와 원문 문자열을 안전한 텍스트 셀로 보존합니다. 원문과 파일 다운로드 시 소유권·권리 모드·파일 경로·SHA-256을 다시 검사합니다.

검증은 통과·반올림 차이·확인 필요·검사 불가를 구분합니다. 읽지 못한 값은 통과가 아니며, 총자본과 지배기업 귀속자본을 혼동하지 않습니다. 표시 정밀도를 모르면 임의의 반올림 허용오차를 적용하지 않습니다. 검증 결과는 원문 수치를 수정하지 않습니다.

## 운영 확인과 중지

`analysis_jobs`의 대기·실패·임대 만료, `analysis_runs`의 부분 성공과 재시도 시각, 자료 확보율, 원문 추출 실패와 저장량을 확인합니다. 재실행과 프로세스 재시작은 완료된 원문·제출본을 재사용합니다. 화면 조회 자체는 제공자 수집을 실행하지 않습니다.

장애 시 단계별 기능 플래그를 끄고 API·워커 설정을 함께 반영합니다. 저장된 원문과 실행 기록은 삭제하지 않습니다. 검증용 테스트 성공과 운영 DART·SEC 수집 성공은 별도로 확인해야 합니다. 13F·OCR·DSD·공동 편집·주문 실행은 포함하지 않습니다.
