# 주기 뉴스 수집과 NAVER 검색 분리

2026-09-05 구현. `/news`는 관심종목과 무관하게 선택된 국내·미국 피드의 전체 뉴스를 보여줍니다. `/news/naver`는 별도 수동 검색 화면입니다. 공시 D001·D002·D005와 SEC 수집은 기존 도메인으로 유지합니다.

## 선택한 소스

| 피드 ID           | 원출처와 범위                             | 구분           | 주기                        |
| ----------------- | ----------------------------------------- | -------------- | --------------------------- |
| `etoday-market`   | 이투데이 증권                             | 독립 언론      | 15분                        |
| `etoday-finance`  | 이투데이 금융                             | 독립 언론      | 15분                        |
| `etoday-industry` | 이투데이 산업                             | 독립 언론      | 15분                        |
| `etoday-economy`  | 이투데이 경제                             | 독립 언론      | 15분                        |
| `fed-press`       | 미국 연방준비제도 보도자료                | 공식 발표      | 15분                        |
| `fed-speeches`    | 미국 연방준비제도 연설·의회 증언          | 공식 발표      | 15분                        |
| `bls-latest`      | 미국 노동통계국 최신 발표                 | 공식 발표      | 15분                        |
| 등록된 기업 IR    | 등록한 RSS·Atom                           | 기업 직접 발표 | 15분                        |
| GDELT             | 원언론사 정책을 승인 목록에 등록한 도메인 | 발견 경로      | 30분, 승인 목록이 있을 때만 |

RSS 제공 안내: [이투데이](https://www.etoday.co.kr/rss/), [Fed](https://www.federalreserve.gov/feeds/feeds.htm), [BLS](https://www.bls.gov/help/hlp_rss.htm). 이투데이는 비상업 RSS 리더 범위로 사용합니다. Fed·BLS도 이번 구현에서는 제목·링크·시각·원출처 메타데이터만 저장합니다. 공식 발표는 독립 언론의 취재 검증과 구분합니다.

매일경제·뉴시스·한국경제TV·Reuters·AP·CNBC는 후보 목록에 두었습니다. 피드 제공 및 저장·표시 조건이 확인되기 전에는 자동 수집하지 않습니다. `APPROVED_GDELT_DOMAINS`와 `APPROVED_GDELT_SOURCE_POLICIES`의 초기 승인 목록은 비어 있습니다. 환경 변수만 추가해 승인 조건을 우회할 수 없습니다.

## 저장과 표시

`source_items`는 출처별 원본 제목·링크·GUID·작성자·분류·발행 시각 필드를 보존합니다. 게시 시각과 최초 관측 시각은 별도로 저장하고 화면에는 KST로 표시합니다. 날짜의 시간대가 불명확하면 게시 시각을 추측하지 않습니다.

`news_articles`는 추적 매개변수와 URL fragment를 제거한 원문 URL을 기준으로 여러 출처를 연결합니다. 기사 식별에 쓰이는 다른 URL 매개변수는 유지합니다. 출처 행을 삭제하거나 덮어 합치지 않으며, 대표 항목과 함께 발견 출처 수를 제공합니다. 같은 사건의 서로 다른 URL까지 자동으로 병합하는 기능은 포함하지 않습니다.

시장·출처 종류·매체·검색어로 필터링합니다. 페이지 커서는 기사 묶음의 고정 정렬 시각과 ID를 사용합니다. 회사명·별칭이 제목에서 한 회사에 명확히 대응할 때만 회사와 연결합니다. 연결되지 않은 경제·산업 뉴스도 전체 뉴스에 표시합니다.

모든 새 항목에 저장·표시·AI·전문 저장·재배포·알림 권한을 따로 기록합니다. RSS·IR 기본 정책은 AI, 전문 저장, 공개 재배포, 외부 알림을 허용하지 않습니다. AI 번역은 개별 항목에서 `aiAllowed === true`일 때만 생성·표시·검색에 사용합니다. 불명확한 권한을 허용으로 취급하지 않습니다.

## NAVER 수동 검색

`GET /api/v1/news-search/naver`는 인증된 사용자의 명시적 검색 요청에만 응답합니다. 검색어는 UTF-8 percent encoding 후 `X-Orsem-News-Query`에 넣고, 시작 위치와 정렬은 `X-Orsem-News-Start`, `X-Orsem-News-Sort` 요청 헤더로 전달해 일반적인 프록시 URL 접근 로그에 남기지 않습니다. 복호화한 검색어는 1–120자, 시작 위치는 1–1000, 정렬은 `date` 또는 `sim`, 요청당 표시 수는 20개입니다. 제공자 설정에 따라 고정된 Developers 또는 API HUB 주소에만 요청합니다.

원래 결과 순서와 표시 필드를 유지하며 브라우저 컴포넌트 메모리에서만 일시 표시합니다. DB, Redis, React Query, localStorage에 결과를 저장하지 않습니다. 응답은 `Cache-Control: no-store`이며 AI·임베딩·통합 뉴스·통합 검색·푸시 알림에 전달하지 않습니다. 기존 저장 행은 삭제하지 않고 조회·재처리 경로에서 제외합니다. 과거 NAVER 반복 작업과 공시 연동 P3 작업, 남아 있는 outbox·푸시 작업도 실행 단계에서 차단합니다.

## 설정과 배포

```dotenv
NEWS_RSS_FEEDS=etoday-market,etoday-finance,etoday-industry,etoday-economy,fed-press,fed-speeches,bls-latest
GDELT_NEWS_DOMAINS=
```

피드 설정은 명시적으로 선택하며 키가 필요하지 않습니다. IR은 기존 등록 목록을 사용합니다. 비밀 설정은 저장소 밖에서 관리합니다. 새 API·worker 실행 전 `AddNewsArticles1788401000000`을 적용해야 합니다. `synchronize=false`를 유지합니다. 배포 전 기존 미적용 마이그레이션을 확인하고, 다른 도메인의 데이터 보정 작업을 뉴스 배포와 섞어 실행하지 않습니다.

`orsem-market-news` 큐가 RSS·IR·승인 GDELT 작업을 담당합니다. 기존 SEC 작업은 기존 커넥터 큐에 유지합니다. worker 시작 시 알려진 과거 뉴스 반복 작업만 제거하고 새 주기를 등록합니다. 다른 작업과 큐 전체를 삭제하지 않습니다.

피드별 `RSS_HTTP:<URL SHA-256>` 체크포인트에 ETag·Last-Modified를 보존합니다. 해당 응답의 기사 저장이 완료된 뒤에만 조건부 요청 정보를 갱신합니다. `304`는 정상 수집 확인으로 기록합니다. 일부 피드 실패는 성공한 피드의 저장을 막지 않으며, 실패 피드의 마지막 성공 시각을 현재 시각으로 덮어쓰지 않습니다. `/api/v1/sources`와 운영 소스 화면에서 개별 피드 신선도를 확인할 수 있습니다.

실제 운영 확인은 첫 수집 건수, 피드별 HTTP 상태, 다음 반복 작업, 재실행 시 중복 증가 여부, 기존 NAVER 행 비증가 및 통합 API 제외 여부를 함께 확인합니다. 빌드·테스트 성공만으로 운영 수집 시작을 판단하지 않습니다.
