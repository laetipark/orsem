# 국내·해외 뉴스 갱신 및 종목 오인식 복구 — 2026-09-24

이 문서는 2026-09-24 당시의 수집·화면 동작과 복구 결과를 기록합니다. 이후 NAVER 메타데이터 저장과 통합 최신순 목록은 [뉴스 수집](NEWS_COLLECTION.md) 및 [2026-09-25 배포 기록](NEWS_UNIFIED_DEPLOYMENT_2026-09-25.md)을 참고합니다.

## 확인한 원인

- NAVER Cloud 검색은 무료 이용 확인 기간이 2026-09-13 00:00 KST에 끝나면서 중단됐다. 키 유무와 실제 호출 가능 상태를 구분하지 못하는 화면 문구도 남아 있었다.
- SEC는 외부 403 `SEC_UNDECLARED_AUTOMATION` 응답으로 공통 대기 중이었다. 2026-09-24 점검 시 62회 연속 실패 기록, 다음 허용 시각은 20:31:29 KST였다. 이번 배포는 이 차단이나 대기 상태를 초기화하지 않는다.
- 공식 RSS의 발행일과 수집 확인 시각은 서로 다르다. 성공한 304 확인, 새 자료 없음, 일부 실패, 수집 지연을 분리해야 한다.
- `NEW`의 회사명 별칭이 일반 영단어 `new`와 대소문자 구분 없이 일치했다. 자동 관계 31개와 뉴스·출처의 primary 회사 2개가 잘못 연결돼 있었다.

## 변경

### NAVER 검색

`NAVER_NEWS_FREE_VERIFIED_AT`과 `NAVER_NEWS_FREE_UNTIL`로 최대 30일의 확인 기간을 지정한다. 새 형식을 쓰면 월이 바뀌어도 확인 기간 안에서는 검색하며, 일·월 사용량 카운터와 15분당 10회 제한은 그대로 적용한다. 기존 형식만 쓰는 설정은 기존의 보수적인 월별 제한을 유지한다. 만료 7일 전 경고와 만료·설정 오류 사유를 제공한다.

기존 종목 검색과 국내 증시·한국은행 기준금리·원달러 환율, 미국 증시·연준 금리·미국 경제, 기존 5개 자산 주제를 교대로 검색한다. 하나의 조회 오류가 다음 주제를 막지 않되 인증·공통 한도 오류는 중단한다. 별도 유료 제공자나 권리가 확인되지 않은 RSS는 활성화하지 않았다.

회원 화면은 `providerResultSets`를 별도 네이버 검색 목록으로 표시한다. 각 검색 응답의 원래 순서, 중복, 제목·요약을 유지하고 출처 링크를 제공한다. 다른 출처와 합쳐 정렬하거나 종목 배지를 덧붙이지 않는다. `groups`는 기존 호환 필드로 남긴다. 원문은 DB·로그·AI에 저장하지 않으며 서버와 화면 캐시는 만료 시 제거한다. 동일 검색의 다음 요청 직전에 이전 서버 캐시를 폐기한다.

### 종목 연결

공통 TypeScript/Python matcher 버전은 2다. NEW/NICE처럼 일상어와 충돌하는 이름은 그 이름만으로 회사 관계를 만들지 않는다. 정식 회사명, 등록된 고유 별칭, 해당 시장에 맞는 명시적 종목 표기 등 별도 근거가 필요하다. 예를 들어 `new policy`, `NEW PRODUCT`, `NASDAQ:160550`은 NEW의 근거가 아니다. KRX 종목코드 `160550`의 명시적 표기는 지원한다. NAVER의 NEW 검색어도 정식 영문 회사명을 사용한다.

`news-repair`는 지정한 회사의 구버전 자동 관계만 대상으로 한다. 기본은 dry-run이며 적용에는 외부 비공개 before/after 백업, 범위 제한, 트랜잭션을 사용한다. 공식 IR·수동·제공자 관계와 원시 필드, 권리, 시각은 보존한다. `news-repair-rollback`은 현재 상태가 적용 후 스냅샷과 일치할 때만 복원한다.

### SEC와 RSS

SEC의 기업별 네트워크·응답 오류는 격리하고 부분 실패를 기록한다. 공통 403/429 대기, 정책 오류, DB와 체크포인트 오류는 전체 요청을 중단한다. CLI 대상에는 승인된 개인·공유 관심그룹도 포함한다.

RSS 연결 시 검증한 DNS 주소의 연결 자체가 실패하면 같은 DNS 응답의 다음 주소를 남은 총 제한시간 안에서 시도한다. 주소를 다시 조회하거나 TLS 검증을 완화하지 않으며, 인증서·HTTP 응답·본문 수신 실패는 이 방식으로 재시도하지 않는다.

## 검증 및 배포

- 격리된 contracts/database/API 컴파일, 웹 타입 검사·프로덕션 빌드 통과.
- 배포 수집기 후보: 329개 테스트 통과, 선택 Redis 통합검사 1개 생략, 모듈 60개 가져오기 통과.
- 웹 관련 회귀검사 52개와 NAVER/config 관련 46개 통과. 수집 시각, 오류 격리, 만료, NEW 검색어·오인식 및 원래 응답 순서를 포함한다.
- API 실제 배포 모듈의 DI·컨트롤러·수집 상태를 별도 mock smoke로 검증했다.
- 브라우저 격리 화면에서 국내·해외 묶음, KST, 원래 순서, 출처 링크를 확인했다. 운영 회원 화면은 로그인 세션이 없어 직접 검증하지 못했다.
- 기존 변경을 포함하는 전체 빌드를 덮어쓰지 않았다. API는 지정 모듈과 메서드만 교체했고 보호 파일 553개 해시를 유지했다. 웹은 기존 운영 78개 파일을 재현하는 기준 소스에 이번 변경만 추가했다. 수집기는 운영 패키지의 6개 파일만 변경하고 나머지 62개 파일과 의존성 44개를 보존했다.
- 운영 연결 정리 결과: 31개 출처의 NEW 자동 관계 31개 제거, primary 2개 해제. 등록 IR 관계 22개와 다른 종목 자동 관계 99개 보존. NICE 변경 없음.

## 운영 실측

2026-09-24 18:00:30 KST에 배포된 NAVER 서비스와 실제 사용량 예약을 거쳐 검색 1회를 검증했다. 미국 증시 검색에서 기사 20건이 반환됐으며 발행 시각은 당일 10:48–17:46 KST였다. 검증 후 일 잔여 989회, 월 잔여 27,441회, 15분 창 잔여 9회였다. 기사 내용은 검증 자료에 저장하지 않았다.

18:00 및 18:15 KST의 두 자연 예약 주기에서 IR과 NEWS_RSS 작업·ingestion run이 모두 완료됐다. Samsung IR과 공식 RSS 5개의 실제 feed checkpoint는 모두 HTTP 304였으며 실패·누락 건수는 0이었다. 마지막 성공 시각은 IR 18:15:09 KST, NEWS_RSS 18:15:19 KST로 갱신됐다. 다음 18:30 예약도 유지됐다. 이는 새 자료가 없는 정상 확인이며 새 기사 생성으로 기록하지 않았다.

18:11 KST에는 NAVER 정기 작업의 추가 9회 호출도 사용량 기록으로 확인했다. SEC는 20:31:29 KST까지 요청을 보내지 않는 공통 대기를 유지했다.

## 운영 및 복구

배포·DB·설정·큐 백업과 복구 자료는 저장소 외부의 비공개 디렉터리에 있다:

`../orsem-data/backups/news-recovery-20260924T084300Z`

`manifest.json`과 `runtime-verification.json`은 배포 해시·상태, `news-repair/report.json`은 데이터 정리 결과를 기록한다. DB 전체 압축 스냅샷과 `news-repair`의 before/after 이미지는 원시 데이터를 포함하므로 공개하거나 저장소에 추가하지 않는다.

`apply-release.cjs rollback <백업 디렉터리>`는 큐 대기, 환경 해시 확인 후 이전 런타임을 복원한다. 데이터 복원은 별도의 `news-repair-rollback --repair-dir <백업>/news-repair --output-dir <새 외부 디렉터리>`로 먼저 모의 실행한다. 실제 복원은 명시적 `--apply`가 필요하다. 전체 DB 스냅샷 복원은 이 작업의 자동 롤백에 포함하지 않는다.

무료 확인 기간은 2026-09-24 17:41:11 KST부터 2026-10-24 17:41:11 KST까지 갱신했다. 일 1,000회·월 30,000회의 기존 보수적인 한도는 유지했다.

화면은 15분 호출 한도에 따른 정상 대기를 “다음 검색 대기”와 다음 요청 가능 시각으로 표시한다.

실제 운영 메타데이터의 `discoveryCreated`, `partialFailureCount`, `issuerFailureCount`를 인식하는 표시 보완을 API에 추가 반영했다. 수집기는 이 보완에서 재시작하지 않았다.

SEC 접근 문제는 별도의 외부 차단이다. 대기시간을 우회하지 않으며 webmaster 문의 초안은 비공개 백업에만 보관하고 전송하지 않았다.
