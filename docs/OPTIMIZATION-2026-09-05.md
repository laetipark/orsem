# 메모리·조회·반응형 개선 검증

## 적용 범위

- AI 모델, 컨텍스트 4,096, 동시 처리 1개를 유지하고 마지막 추론 후 유휴 유지 시간을 30분에서 5분으로 변경했습니다.
- 이벤트 관계·공시 사실과 기업별 관심·최근 이벤트를 요청 단위로 묶어 조회합니다. 대시보드에서 사용하지 않는 상세 조회를 제거했습니다.
- 뉴스 목록은 필요한 열만 읽고 출처를 한 번 분류합니다. 목록의 본문 검증은 전체 블록 배열을 복사하지 않습니다. 상세의 정제 결과는 한 번만 생성합니다.
- 시장 지표 갱신은 입력 키와 직전 비교값만 조회합니다. 정정 우선순위, 최초 관측 시각, 원문 정보는 유지합니다.
- OpenDART 응답 읽기를 공통 크기 제한 함수로 통합하고 초과 응답의 스트림을 취소합니다.
- 사용하지 않는 기사·차트 조회 캐시는 2분 후 해제하고 요청 중 화면을 떠나면 취소합니다. 시장 차트는 데이터·테마 변경 때 인스턴스를 재사용합니다.
- 900px 이하 이벤트·운영 기록은 이름표가 있는 카드로 표시합니다. 표와 카드를 동시에 생성하지 않습니다. 620px 이하 메뉴는 아이콘·이름을 포함한 동일 너비 5칸입니다.
- 뉴스 카드는 번역 제목·번역 요약만 표시하며 번역 요약이 없으면 생략합니다. 상세에서는 제목 아래의 번역/원문 선택으로 제목·요약·본문을 함께 전환합니다. 선택한 본문만 생성하며 기사 이동 때 번역으로 초기화합니다.
- `disclosure-strip`은 오늘 접수 건수를 크게, 전체 수집 누적을 작게 표시합니다. KST 접수일 기준과 전체 기간 목록으로 이동한다는 설명을 표시합니다.
- 커넥터 신선도는 공식 공시 → 시장 데이터 → 뉴스 → 기타 순서로 묶고 같은 그룹 안에서 이름·ID 순서로 정렬합니다.

기존 URL·필터·권한·알림과 REST 필드는 유지합니다. 대시보드의 `totalCounts`만 선택적 필드로 추가했으며 DB 마이그레이션은 없습니다. 영문 뉴스 번역 완료·해시·권리 검증과 DART/SEC/네이버 별도 검색의 기존 범위를 유지합니다.

## 동일 데이터 조회 비교

변경 전 빌드와 변경 후 빌드를 동일한 읽기 전용 `REPEATABLE READ` 트랜잭션에서 호출했습니다. 아래 시간은 네트워크를 제외한 서비스 호출 시간이며 준비 조회 후 3회 측정한 중앙값입니다. 캐시·서버 부하에 따라 달라질 수 있습니다.

| 요청        | DB 조회 전 → 후 |   중앙값 전 → 후 |
| ----------- | --------------: | ---------------: |
| 뉴스 20건   |           2 → 2 |   12.47 → 9.38ms |
| 이벤트 20건 |        241 → 12 | 337.48 → 26.24ms |
| 기업 20건   |          47 → 3 |   50.72 → 7.24ms |

각 목록은 1건·20건 조건에서 시각 필드를 제외한 응답이 모두 일치했습니다. 뉴스 손상·권리 불일치 등에 대한 기존/신규 구현 비교 1,980개 조합도 일치했습니다.

대시보드는 최종 공시 그룹 집계를 포함해 DB 조회가 **101회에서 25회**로 줄었습니다. 오늘 값은 KST 접수일로 계산하며 예전 공시를 오늘 처음 관측해도 오늘 접수로 세지 않습니다. 2026-09-05 운영 확인 당시 오늘 접수는 모두 0건, 전체 수집은 D001 277 / D002 328 / D003 17 / D004 4 / D005 19건으로 실제 DB 및 연결 이벤트 수와 일치했습니다.

## 메모리와 입력 범위

뉴스 본문 2,000블록을 400회 검증하는 합성 입력을 각각 별도 Node 프로세스에서 실행했습니다.

| 항목                  |   변경 전 |   변경 후 |
| --------------------- | --------: | --------: |
| 검증 중앙값           |    6.18ms |    1.92ms |
| 검증 95백분위         |    8.82ms |    2.60ms |
| 관측한 최고 JS 힙     |  44.60MiB |  18.72MiB |
| 프로세스 최대 RSS     | 129.39MiB |  79.41MiB |
| 종료 시 GC 후 힙 변화 | +0.081MiB | -0.001MiB |

이는 검증 함수의 동일 합성 입력 비교이며 운영 API의 전체 메모리 절감률은 아닙니다. 재현 명령은 다음과 같습니다.

```sh
node --expose-gc scripts/benchmark-news-content.cjs apps/api/dist/resources/news-content.js
```

수집 작업자는 종목별 일별 이력 10,000개와 현재값 1개가 있는 같은 합성 데이터에서 비교했습니다. 실제 DB를 변경하지 않고 저장 예정 결과의 일치를 확인했습니다.

| 입력                   | 읽은 행 전 → 후 | 조회 횟수 전 → 후 |
| ---------------------- | --------------: | ----------------: |
| 현재값 1개             |      10,001 → 2 |             1 → 2 |
| 일별 정정 30개         |     10,001 → 60 |             1 → 2 |
| 일별 정정 401개        |    10,001 → 802 |             1 → 6 |
| 비교값이 제공된 현재값 |      10,001 → 1 |             1 → 1 |
| 빈 입력                |           0 → 0 |             1 → 0 |

5개 조건의 저장 예정 결과는 정정 비교값과 최초 관측 정보를 포함해 일치했습니다. 행 수는 애플리케이션으로 반환되는 논리적 조회량이며 DB 내부 탐색 행 수나 운영 RSS를 뜻하지 않습니다. 조회 횟수를 일부 늘리는 대신 전체 이력과 원본 메타데이터 전송·객체 생성을 제거했습니다.

뉴스·이벤트·기업 목록 20건씩을 각각 30회 반복한 별도 Node 프로세스 검사에서도 응답 해시가 모두 일치했습니다. 총 DB 조회는 8,700회 → 510회, 소요 시간은 4.18초 → 0.98초였습니다. 5회 간격 GC 후 힙은 이전 27.426~~27.636MiB, 이후 27.084~~27.439MiB로 관측 구간에서 큰 누적 증가가 없었습니다. 최종 RSS는 152.19 → 154.18MiB여서 이 검사로 전체 프로세스 RSS 감소를 주장할 수는 없습니다.

## 화면·회귀 검증

- 실제 Chrome에서 320·375·620·621·768·900·901·1100·1101·1440px를 확인했습니다. 대시보드, 이벤트, 운영, 기사 상세, 기업 상세에 문서 가로 넘침이 없었습니다.
- 900px 경계 양쪽에서 표 또는 카드 하나만 존재했습니다. 기사/시장 차트 화면을 3회 반복 이동해 기사 본문 1개, 차트 화면 캔버스 7개가 유지됨을 확인했습니다.
- 기사 언어 전환 시 제목과 본문 언어가 함께 바뀌며 숨겨진 다른 언어 본문은 생성되지 않았습니다. 모바일 라이트 테마와 다크 테마, 차트 기간 변경 및 데이터 표 열기/닫기도 확인했습니다.
- 활성 쿼리는 유지하고 마지막 사용자가 떠난 조회는 취소하는 동작, 2분 후 비활성 캐시 제거, 차트 인스턴스 재사용을 자동 테스트로 확인했습니다.
- 실제 운영 출처 페이지에서 공식 공시 2개 → 시장 데이터 6개 → 뉴스 7개 → 기타 1개 순서를 확인했고 10개 너비 모두 가로 넘침이 없었습니다. 운영 공시 카드의 오늘/누적 값과 링크도 확인했습니다.
- `npm run check`와 `npm run build`가 통과했습니다. 최종 테스트는 스크립트 33, API 221, Discord 4, 웹 184, 작업자 395, contracts 20, database 33, 파서 115개로 **총 1,005개**입니다.

브라우저 도구에서 JS 힙 수치를 직접 제공하지 않아 브라우저 메모리 절감률은 산출하지 않았습니다. 반복 이동의 DOM/캔버스 개수와 자원 수명 테스트는 통과했지만 장시간 누수가 없음을 입증하는 검사는 아닙니다.
