# OpenDART 파싱 무결성 및 재검증

이 작업은 공시 수집·분류·파싱·검토 시스템의 품질 개선입니다. 거래 실행이나 투자 판단을 추가하지 않습니다. 원문, 과거 파싱 결과, 수동 검토 관계를 삭제하지 않으며 비활성 재검증 결과는 이용자 시세·거래 알림에 사용하지 않습니다.

## 유형과 활성 결과

`filings`는 API 원본 유형, 제목 감지 유형, canonical 유형, 분류 상태·버전·근거를 따로 보존합니다. 목록 요청에 넣은 유형 필터는 원본 유형의 증거로 사용하지 않습니다. D001~D005를 각 도메인의 추출기로 처리합니다. D003은 의결권 위임 권유, D004는 공개매수이며 보유변동·거래계획 추출기를 공유하지 않습니다. 모호한 분류는 `UNKNOWN` 또는 `CONFLICT`, 명시적인 수동 유형은 `MANUAL_OVERRIDE`입니다.

새 실행의 재사용 키는 원문 SHA, parser·normalizer·classifier 버전, extractor 유형과 문서 하위유형으로 계산합니다. 과거 실행의 입력 유형은 현재 공시 유형으로 추정해 채우지 않습니다. 활성화 전 canonical, input, extractor, 실제 결과 유형이 모두 일치해야 합니다. `REJECTED` 결과와 원문 교차검증을 마치지 않은 결과는 수동 확인으로도 활성화할 수 없습니다.

API는 명시적인 활성 포인터와 검증을 통과한 결과만 읽습니다. 최신 실행으로 자동 대체하지 않으며, 현재 유형과 다른 과거 투영 행은 노출하지 않습니다. 공시 알림은 생성뿐 아니라 fan-out, 웹 푸시, 봇 pull 시점에도 현재 유형과 활성 실행을 재확인합니다. 뉴스 알림은 이 공시 전용 규칙과 분리됩니다.

## XML과 표 추출

버전은 `opendart-xml-v3`, `opendart-dialect-v1`, `opendart-title-v2`입니다. 원본 ZIP/XML은 불변이며 파싱용 사본만 결정론적으로 정규화합니다. 정상 XML은 no-op이고, 정규화된 사본도 다시 엄격 XML 검증을 통과해야 합니다. 보정 위치·개수·바이트 비율·원본 및 결과 SHA·원래 검증 오류를 보존합니다.

DTD, 외부 엔티티, XInclude, 네트워크 조회를 허용하지 않습니다. ZIP 경로·파일 수·크기·압축률과 XML 깊이·노드·속성·보정 한도를 적용합니다. 모호한 속성 복구를 일반 HTML 파싱으로 우회하지 않습니다.

TD/TH/TE/TU, rowspan/colspan, 다중 헤더를 논리 표로 만들고 각 필드의 원본 좌표와 헤더 경로를 남깁니다. 수량과 금액·비율 헤더를 구분합니다. 정정 전후 비교표는 본문 거래표로 중복 추출하지 않습니다. 표 없음, 필수 헤더 없음, 데이터 없음, 유효 행 없음은 별도 경고입니다. 수량 부호만으로 시장 매수를 추정하지 않습니다.

## 검토 이력과 UTC 이관

`AddParseIntegrity1788399000000`은 기존 OPEN 파싱 검토를 감사 테이블에 보존한 뒤 같은 공시의 이전 OPEN을 `SUPERSEDED`로 연결합니다. 생성 열의 unique key가 공시별 OPEN 파싱 검토 하나를 보장합니다. 수동으로 닫힌 검토를 자동으로 덮어쓰지 않고 새 근거의 검토에 이력을 연결합니다.

모든 MySQL 연결은 대여 시점마다 서버 세션도 UTC로 설정합니다. `timezone: 'Z'`만으로 DB의 `CURRENT_TIMESTAMP` 기준이 바뀌지는 않습니다. 원본 날짜는 날짜로 유지하며 API·CSV 표시 시각만 KST로 한 번 변환합니다.

`RepairLegacyParserClock1788400000000` 실행 전 기존 저장 기준을 진단해야 합니다. 기존 UTC 데이터는 `ORSEM_LEGACY_PARSER_TIME_ZONE=UTC`, 이 호스트에서 확인한 과거 KST 기본값은 `+09:00`을 해당 마이그레이션 프로세스에만 주입합니다. 판단 없이 다른 DB에 `+09:00`을 복사하지 않습니다. 기존 데이터가 있는데 기준을 지정하지 않으면 이관은 중단됩니다.

보정 범위는 과거 파싱 실행과 관련 검토입니다. `parser_clock_corrections`에 원래 시각·보정 시각·근거를 보존합니다. 일부 과거 `updated_at`은 초 단위로 절삭되어 `created_at`보다 1초 미만 앞서므로 그 정밀도를 임의로 늘리지 않습니다. 1초 이상 역전이나 미래 보정은 중단합니다. 실행 중인 writer를 정지하고 백업한 뒤 이관하며, 재시작할 때는 UTC 연결을 사용하는 새 API와 worker를 함께 반영합니다.

MySQL DDL은 자동 커밋됩니다. 첫 무결성 이관이 중간에 실패하면 schema와 `typeorm_migrations`를 확인한 후 복구해야 하며 무조건 처음부터 재실행하지 않습니다. 시간 보정은 감사된 원래 값 또는 이미 보정된 값에만 적용하여 이중으로 9시간을 빼지 않습니다. 두 이관의 `down`은 감사 이력 삭제를 의도적으로 거절합니다.

## 외부 원문을 사용하는 전수 회귀

비밀과 원문은 저장소 밖에 보관합니다. 아래 명령은 개발·격리 후보의 Python 소스를 사용하며 경로는 운영자가 준비한 외부 감사 파일입니다. 환경 설치는 [Python 워커 안내](PYTHON_WORKER.md#실행-환경)를 따릅니다. 운영 wheel을 감사하려면 같은 안내의 `-I -B -m orsem_worker.cli` 진입점에 각 스크립트 이름에서 `.py`를 뺀 하위 명령을 사용합니다.

```sh
.venv/bin/python scripts/parser-corpus-audit.py \
  --snapshot ../orsem-data/snapshot.json \
  --old-results ../orsem-data/old-results.json \
  --output-dir ../orsem-data/corpus-audit
.venv/bin/python scripts/stage-parser-corpus.py \
  --snapshot ../orsem-data/snapshot.json \
  --corpus ../orsem-data/corpus-audit/corpus-audit.json \
  --output-dir ../orsem-data/staging-dry-run
```

하네스는 모든 원문 변형을 검사하며 공시 ID로 중복 제거하지 않습니다. 입력 SHA와 버전, 엄격 XML 검증, no-op/idempotence, 필드별 이전 결과 비교, 경고·원문 좌표를 기록합니다. 출력을 저장소 안에 생성하지 않습니다.

`scripts/stage-parser-corpus.py`는 기본적으로 DB에 연결하지 않습니다. `--apply`와 명시적인 `ORSEM_STAGE_DATABASE_URL`을 함께 제공해야 비활성 결과를 저장합니다. 테스트용 로컬 소켓은 `ORSEM_STAGE_SOCKET_PATH`로 지정합니다. `.env`에서 staging 대상 DB를 자동 선택하지 않습니다. 이 명령은 외부 커넥터를 부르거나 작업·알림을 enqueue하지 않으며 활성 포인터를 바꾸지 않습니다.

비활성 결과의 검토 화면에서 첫 `공식 요약 검증`은 동일 접수번호의 공식 요약만 조회하고 OPEN 검토를 유지합니다. API 요청이 성공해도 해당 접수번호가 없으면 검증 완료로 취급하지 않습니다. D005는 공식 요약 비대상입니다. D003·D004도 전용 요약 API가 없으므로 비대상 사유를 기록하되, 이것만으로 원문 대조 완료로 처리하지 않습니다. D003·D004는 관리자 `원문 대조 완료`가 실행 ID·원문 SHA·관리자·UTC 시각에 묶여 저장된 후 별도의 `검토 확정`으로 활성화합니다. 관리자가 저장된 요약과 원문·추출 필드를 확인한 다음 별도의 `검토 확정`을 요청해야 기존 활성화 검증을 진행합니다. 작업 payload의 `crosscheckOnly`는 첫 검증 작업이 재전달돼도 활성화로 바뀌지 않도록 고정합니다.

전체 입력을 재검증한 뒤 공시별 트랜잭션으로 저장합니다. 원문이나 제목이 바뀌었거나 corpus 밖의 새 원문이 있으면 중단합니다. 일부 공시를 저장한 뒤 중단된 경우 같은 corpus로 다시 실행하면 fingerprint가 같은 실행을 재사용합니다. 모든 입력 저장 및 최종 보존 검증이 끝나기 전에는 완료로 간주하지 않습니다.

## CSV와 운영 지표

```sh
.venv/bin/python scripts/export-parser-review-audit.py --output-dir ../orsem-data/parser-review-export
```

도구는 UTC·READ ONLY·REPEATABLE READ 트랜잭션의 동일 스냅샷에서 실패 실행, OPEN 검토, 최신 실행 집계를 내보냅니다. `created_at > snapshot_at`이면 성공 CSV를 만들지 않습니다. 결과 파일은 권한 0600이며 UTF-8 BOM, 전체 셀 인용, 수식 방어를 적용합니다. 접수번호·종목코드 등 불투명 식별자는 Excel의 자동 숫자 변환을 막는 텍스트 표식을 사용하고 manifest에 이를 명시합니다.

관리자 대시보드·운영 화면은 전체 실행, OPEN 행, 현재 고유 검토 대상, 최신 미복구 공시, 현재 실패, 오래된 OPEN, 원문 미제공, 관계 검토를 구분합니다. 역사적 실패는 삭제하지 않으므로 누적 실패 수가 0이 되는 것이 목표가 아닙니다. 파서 실패는 검토 목록에 이미 포함되므로 두 수치를 합산하지 않습니다.

## 백업·복원 확인과 배포

실행 중인 API/worker의 빌드 디렉터리에서 후보 코드를 빌드하지 않습니다. `python3 scripts/verify-in-isolation.py`로 검증한 명세의 API·계약·DB와 Python worker wheel을 사용하며, 실제 변경한 실행 단위만 교체합니다. 관련 테이블 데이터, 마이그레이션 이력, 처리 outbox/알림 대기를 권한 0600의 외부 파일로 백업합니다. 원본 문서는 기존 불변 저장소에 유지합니다.

```sh
.venv/bin/python scripts/parser-rollout-backup.py backup \
  --env-file ../orsem-data/runtime.env --output-dir ../orsem-data/rollout/attempt-1/backup
.venv/bin/python scripts/parser-rollout-backup.py restore-check \
```
