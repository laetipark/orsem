## 수정

- Python과 API 설정 검증에서 User-Agent 전체에 출력 가능한 ASCII를 요구한다. 기존 정규식은 첫 문자만 ASCII로 제한하여 뒤에 한글·NUL·TAB 등이 섞여도 통과했다. Python HTTP 클라이언트는 비ASCII 헤더를 요청 생성 시 거부하므로 설정 단계에서 명확히 알린다.
- 공통 `SecHttp`가 SEC GET 요청에 설정 User-Agent를 강제한다. 기존 네 수집 경로는 이미 명시적으로 전달했지만, 공통 호출에서 헤더를 생략하면 라이브러리 기본 User-Agent가 사용되는 잠재적 결함을 막았다. 설정이 없으면 요청 슬롯 예약과 네트워크 요청 전에 실패한다.
- 헤더 대소문자·중복을 정리하면서 Accept 등 다른 요청 헤더를 유지한다. SEC가 아닌 호스트의 헤더는 변경하지 않으며 리다이렉트도 추적하지 않는다.
- 기존 실제 연락처와 초당 1회 공유 제한, 영속 cooldown, 데이터·알림 처리는 유지한다.

이 보완은 헤더 오류를 예방한다. 현재 운영의 기존 User-Agent는 이미 조건을 충족했으므로, 수정만으로 이번 SEC 403이 해결됐다고 판정할 수 없다. 저장된 대기 시각 이후 정기 worker의 실제 2xx와 공시 저장 결과가 복구 확인 기준이다.
