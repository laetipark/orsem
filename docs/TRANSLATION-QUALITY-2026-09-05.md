## 같은 입력으로 모델 비교

운영 모델은 Ollama 0.33.2의 `qwen3.5:4b-q4_K_M`이며 CPU로 실행한다. 요청은 `temperature=0`, 문맥 4096, 최대 출력 1200, `think=false`다. 설치 모델의 `presence_penalty=1.5`가 요청에 상속되는 것도 확인했다. 이 설정 하나가 모든 오류의 원인이라는 근거는 없다.

먼저 핵심 오류가 있는 8개 입력을 고정했다. 저장된 기사 전체 번역과 새 단일 문단 번역은 문맥이 다르므로 동일 실험으로 간주하지 않는다. 아래 비교는 같은 제목·요약 또는 같은 본문 블록을 각 설정에 넣어 새로 실행한 결과끼리의 대조다.

- 상세한 영문 지침과 평탄한 출력 형식: 개선과 퇴행이 섞였고 8건 모두 중간 이상 잔여 오류가 있었다. 채택하지 않았다.
- 기존 요청에 `presence_penalty=0`만 지정: 개선 1건, 퇴행 2건, 핵심 문제 유지 5건. 채택하지 않았다.
- 사고 모드: 첫 입력이 120초 제한에 도달해 출력이 없었다. 두 번째 실행을 중단했고 나머지는 측정하지 않았다. 이 실험으로 번역 품질을 판단하지 않는다.
- TranslateGemma 4B: 한국어 전용 번역 지침으로 제목·요약·본문 문자열을 각각 번역하고 원래 구조를 프로그램에서 조립했다. 최초 8건 외에 결과를 보기 전에 정한 별도 기사 4건도 비교했다. 핵심 제목 오역은 개선했지만 요일 누락, 시간대 변경, 본문 조건 삭제가 남았다. 운영 교체 대상으로 채택하지 않았다.
- TranslateGemma 12B: 같은 12개 입력과 전용 지침으로 비교했다. 기존 Qwen 대비 개선 6건·개선과 퇴행 혼재 3건·퇴행 2건·동등 1건이었다. 진단용 8건에서는 각각 5·2·1·0건, 별도 기사 4건에서는 각각 1건이었다. 잘린 요약에 원문에 없는 제품 기능을 완성해서 추가하거나 처분 안내에 원문에 없는 사실 확인을 덧붙이는 핵심 오류가 남았다. 이 모델도 즉시 운영 교체 대상으로 채택하지 않았다.

4B의 전체 12건은 Qwen 대비 개선 3건·혼재 5건·퇴행 2건·동등 2건이었다. 모델뿐 아니라 각 모델에 맞는 프롬프트와 필드별 요청 형식도 달라졌으므로 가중치만 바꾼 실험은 아니다. 기존 운영 클라이언트의 모델 이름만 바꿔도 같은 결과가 나온다는 의미도 아니다. 전용 모델 연결에는 해당 요청 형식을 구현한 어댑터가 별도로 필요하다.

한 번씩 측정한 사례별 전체 처리 시간이며 제목·요약의 복수 호출도 포함한다. 모델 로딩, 캐시 상태, 요청 포장 방식의 영향은 분리하지 않았다. 12B 실행 프로세스는 3초 간격 100회 측정에서 최고 RSS 9.36GiB를 기록했다. 종료 시 이 모델을 메모리에서 해제한 뒤 운영 큐를 재개했다. 이 단일 실험으로 메모리 누수 유무나 지속 부하의 최대 사용량을 판단하지 않는다.

번역 전용 모델은 [Google의 TranslateGemma](https://blog.google/innovation-and-ai/technology/developers-tools/translategemma/)이며, [Ollama 공식 배포의 입력 형식](https://ollama.com/library/translategemma)을 사용했다. 모든 실험은 같은 서버 안에서 실행해 외부 번역 API 이용료와 기사 전송이 발생하지 않았다. 서버의 메모리·전력·저장 공간은 사용한다.

## 구현한 검증 개선

`news-translation-facts.ts`와 `news-translation-language.ts`에 공통 검사를 분리했다. 현재는 로컬 번역 결과 검증에서 사용하며, 당시 함께 검증한 Azure 연결 코드는 후속 정리에서 삭제했다.

- 본문·목록 항목·제목뿐 아니라 값이 있는 요약도 한국어 여부를 확인한다. 지배적인 영문 잔존, 새로 섞인 중국어·일본어·아랍어·키릴 문자, 본문이 극단적으로 짧아진 출력을 거절한다.
- 원문에서 그대로 옮긴 영문 기관명·제품명, URL·이메일, PDF 같은 비언어 표지는 정상적으로 처리한다.
- 날짜의 월과 요일, 수량·부호·백분율·금액·통화·티커를 비교한다. 유리수 계산으로 금액 자릿수를 보존하고 억·천만 혼합 표기와 혼합분수를 비교한다.
- 명시된 시각의 오전·오후와 EDT/EST를 대조한다. 오전 11시와 11:00, 오후 4시 30분과 16:30처럼 같은 24시간 표기는 허용하고, 오후 4시 30분이 4:30으로 바뀌거나 EDT가 동부 표준시로 바뀌는 경우는 거절한다.
- 동일한 금액·금리 범위·날짜의 정상 표기가 잘못 거절되지 않도록 실제 모델 출력과 회귀 입력으로 보완한다.
- 로컬 응답 읽기를 기존 크기 제한 함수로 통합해 자원 해제와 응답 상한을 유지한다.

이 검사는 문장 전체의 의미, 부정·조건, 고유명사의 정확한 번역이나 어느 주체에 수치가 연결되는지를 증명하지 않는다. 요일이 사라진 출력은 막을 수 있지만 원문에 없는 기관명을 한국어로 추가한 모든 경우를 탐지할 수는 없다. 검증을 통과했다는 이유만으로 번역 품질을 인증하지 않는다.

기존의 유효한 완료 기사·원문·자동 번역을 일괄 수정하거나 재번역하지 않았다. 운영의 새 검사는 이후 생성 결과에 적용되며 과거 완료본을 자동으로 교정하지 않는다. 저장된 미완료 조각 재사용과 관리자 편집은 별도 후속 변경의 범위다.

확인된 의미 오류의 후속 수정은 원문·해시를 기준으로 검수한 별도 관리자 수정본에 반영하는 것이 적절하다. 금융 용어와 조건·부정·기관명은 의미 검수가 필요하며, 지금의 검증 코드나 대체 모델 중 어느 것도 이를 완전히 자동 보증하지 않는다.
