# 모바일·브라우저 알림

로그인 후 상단의 **알림 설정**에서 이 계정이 받을 알림 종류와 수신할 브라우저를 설정합니다. 관리자와 승인된 회원이 사용할 수 있으며 처음에는 알림이 꺼져 있습니다.

## 사용자 설정

1. `/settings/notifications`에서 알림을 켜고 공시 접수·분석 완료·정정·뉴스 중 받을 종류를 선택합니다. 관리자는 운영 알림도 선택할 수 있습니다.
2. 관심기업 관련 알림만 받을지 선택하고 설정을 저장합니다. 관심기업은 현재 서비스의 공용 관심 목록을 사용합니다.
3. 이 기기의 알림 연결 버튼을 누르고 브라우저 권한 창에서 허용합니다. 화면을 열기만 해서는 권한을 요청하지 않습니다.
4. 테스트 알림을 보내서 수신과 클릭 이동을 확인합니다. 테스트는 worker의 다음 발송 주기에 전달되므로 약 1분이 걸릴 수 있습니다.

실제 알림은 해당 이벤트·뉴스·운영 화면으로 이동합니다. 로그인이 만료됐다면 로그인 후 원래 화면으로 돌아갑니다. 링크는 서비스 내부의 허용된 경로만 사용합니다. 브라우저의 알림 권한을 차단한 경우 브라우저 설정에서 직접 해제해야 합니다.

Android는 Web Push를 지원하는 Chrome 등의 브라우저에서 HTTPS 주소로 접속합니다. iPhone·iPad는 **iOS/iPadOS 16.4 이상에서 홈 화면에 추가한 웹 앱**을 실행한 뒤 앱 안에서 알림을 허용해야 합니다. [WebKit 공식 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)를 참고하세요. OS 집중 모드·배터리 관리·네트워크 상태에 따라 표시가 늦어질 수 있습니다.

## VAPID 키 설정

별도 유료 업체 가입이나 Firebase 프로젝트가 필요하지 않습니다. VAPID 공개·비공개 키를 서버에서 한 번 생성합니다.

```bash
npm run build -w @orsem/contracts
npm run build -w @orsem/database
npm run push:setup
```

기본 저장 위치는 `/home/laeti/.config/orsem/credentials/web-push.json`이며 디렉터리 `0700`, 파일 `0600`을 사용합니다. JSON은 `publicKey`, `privateKey`, `subject` 문자열을 포함합니다. 실제 키를 저장소나 브라우저 빌드에 넣지 않습니다. 기존 키가 있으면 생성 명령은 덮어쓰지 않고 유효성만 확인합니다.

서버 환경에는 다음 경로를 설정합니다.

```dotenv
WEB_PUSH_CREDENTIALS_FILE=/home/laeti/.config/orsem/credentials/web-push.json
WEB_PUSH_PUBLIC_KEY=
WEB_PUSH_PRIVATE_KEY=
WEB_PUSH_SUBJECT=
```

JSON의 `subject`는 생성 시 `WEB_PUSH_SUBJECT` 또는 서비스의 HTTPS `WEB_ORIGIN`을 사용합니다. 직접 환경 변수로 주입할 때는 `WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_PRIVATE_KEY`, `WEB_PUSH_SUBJECT`를 모두 설정하고 파일 경로는 생략할 수 있습니다. 비어 있지 않은 직접 환경 값이 JSON보다 우선합니다. 키 누락·불일치·잘못된 파일 권한은 Web Push만 비활성화합니다. 공개 키만 인증된 설정 API를 통해 브라우저에 전달합니다.

새 스키마는 `1788397000000-AddWebPush` 마이그레이션으로 적용합니다. 빌드와 마이그레이션 후 API·worker에 같은 키를 주입하여 재시작합니다. 키를 교체하면 사용자가 브라우저 알림 연결을 해제하고 새 공개 키로 다시 연결해야 합니다.

서비스 워커 등록은 `updateViaCache: 'none'`으로 갱신 시 브라우저 캐시를 우회합니다. 설치 정보의 기본 경로는 `/manifest.json`이며 JSON 응답 형식으로 제공합니다. 기존 설치 호환용 `/manifest.webmanifest`도 같은 내용으로 유지합니다. Nginx 배포 예시는 `/sw.js`와 설치 정보 경로에 `Cache-Control: no-cache`를 지정합니다. 기존 TLS 설정을 보존하면서 해당 location만 적용하고 `nginx -t` 후 다시 읽습니다.

## 발송과 운영

- 신규 공시 알림 생성과 신규 뉴스 저장 시 사용자별 대기 발송을 생성합니다. 가입 전 자료나 뉴스 과거 자료를 한꺼번에 보내지 않습니다.
- 매분 기존 outbox 작업에서 전송합니다. 발송 전 계정 승인, 설정, 토픽, 관심기업 범위, 구독 만료와 정정·취소 상태를 다시 확인합니다.
- 설정 변경·구독 해제·승인 취소·원본 알림 취소 시 아직 완료되지 않은 발송을 취소합니다. 이미 Push 서비스로 전달된 알림은 회수할 수 없습니다.
- 중복 키와 발송 점유 시간을 사용합니다. `429`의 재시도 대기 시간을 지키며 최대 6회 시도합니다. `404`·`410` 응답은 만료된 구독을 제거하되 발송 이력을 보존합니다.
- 서비스 워커는 알림 수신과 클릭만 처리합니다. 인증된 API 응답이나 개인정보 페이지를 오프라인 캐시하지 않습니다. endpoint·암호화 키·공급자 오류 원문은 로그에 남기지 않습니다.

자동 테스트에서는 설정 권한, 전송 정책, 공급자 오류, 링크 이동을 검증합니다. 실제 휴대전화 수신은 해당 기기에서 사용자가 알림을 허용한 뒤 테스트 알림으로 확인해야 합니다.
